# くだものキャッチとご飯（2026-10-17）

## 初版の仕様

- 「あそぶ・ごはん」から、育てているキャラで30秒のくだものキャッチを遊ぶ。タマゴ・育成開始前はポケットのこがおともする。
- 指で左右へスライド、左右ボタン、左右矢印キーで移動。完成済みの48×48キャラPNGを整数倍・補間なしで使用。
- 日本時間で1日5回。開始を保存した時点で1回消費し、中断・再読み込みでも回数は戻さない。残り回数は家族内の端末で共有し、午前0時に復帰。
- 参加5pt＋果物1個につき1pt。結果の受取は各ゲーム1回だけ。通信失敗時は結果画面の「もう一度保存する」で再送できる。結果の保存前にページを閉じると未保存スコアは失われる。
- お世話ポイントはご飯専用。親の承認で加減算するご褒美交換ポイント・成長ポイントとは独立。
- きのみ10pt、おさかな15pt、ほかほかスープ20pt。確認後に交換してその場で食べさせ、喜ぶコマを表示。残高減算と食事回数の加算は同一トランザクション。
- 食べ忘れ・遊ばない日のペナルティなし。今回は進化確率を変えない。食事種類別の累積回数を保存し、将来の補正用に拡張可能にする。
- 親は残高と残り回数を閲覧。プレイ・食事は承認済みの子供が操作する。

## 保存と権限

`families/{family}/care/state` の1ドキュメントに日番号、当日回数、残高、最新セッションID・開始時刻・受取状態・スコア、食事種類別回数・最新食事IDを保存する。端末引き継ぎでUIDが変わっても共有記録が残る。累積イベント配列は作らない。

Firestoreルールで家族外・未承認利用者・削除を拒否する。開始日時はserverTimestamp、日番号はrequest.timeから日本時間で検証する。1日5回、30秒経過、1セッション1回の報酬、上限30個のスコア、食事ごとの金額と回数増分を検証する。子供に家族ドキュメントや成長記録への書込権限を追加しない。

スコアそのものはブラウザで算出する。サーバー側ゲーム再現による不正スコア検知は初版の対象外。ルールで1回最大35pt・1日5回までに制限し、実際のご褒美交換には使用できない。端末時刻がサーバーとずれていると開始・終了が拒否される場合があるため自動時刻設定を推奨。

おためしモードだけはメモリを使用し、保存されない旨を画面に明示する。本番の記録をローカル保存で代替しない。

## 検証

`tests/care.test.mjs`：日付境界、5回制限、中断、30秒境界、再送、スコア範囲、食事残高と再送、キャッチ判定。
`tests/rules.test.mjs`：家族外・権限剥奪の拒否、サーバー日付、早期報酬拒否、同時開始・同時受取、残高偽造・食事不足・二重受取拒否、端末共有。

既存のお手伝い・交換・育成・庭のテストも維持する。実際の家族データを試験に使わない。

## 追加ゲーム（2026-10-18）

「あそぶ・ごはん」で3種類から選ぶ。回数・残高・受取処理は既存の同じ`care/state`を使用し、ゲームの種類を変えても合計1日5回。既存の家族データ・権限ルールを変更しない。

### まねっこリズム

- 1フレーズ6秒×5回。3音のお手本の後に、左右の太鼓を同じリズムでタップ。
- 光と文字でも合図する。音はオン・オフを切替可能。左右矢印キーとD/Kにも対応。
- 判定幅は前後260ms。左右とタイミングが一致した音1つにつきボーナス2pt（最大30pt）。同じ音を連打しても二重加算しない。参加5ptは別途付与。
- ページをバックグラウンドにした間は進行を止める。音はWeb Audioの短い合成音で、音源や外部サービスは使わない。

### おべんとうパズル

- 4×4マスへ4種類のおかずを詰める3問。時間制限なし。
- おかず選択→左上の配置マスをタップ、またはドラッグで配置する。「まわす」で90度回転。置いたおかずをタップすると戻せる。
- 「ヒント」は現在の配置から解ける場合に1つ置く。解けない配置では、おかずを戻すよう案内する。「やりなおす」でその問題だけを初期化。
- 完成したお弁当1つにつきボーナス10pt。ヒントによる減点なし。参加5ptは別途付与。「ここまででおわる」で途中までの完成分を受け取れる。
- 必ず解ける完成配置から問題を構成し、ヒントは実際に残りを探索する。完成前後のボタン再操作で二重加算しない。
- 全ゲーム共通の保存ルールに合わせ、開始から30秒より早く終わった場合は、完成画面を表示して残り時間が経過してから報酬を保存する。

### Androidと開始エラー

卵・育成開始前もプレイ可能で、ポケットのこが代役を務める。Androidの一部ブラウザに`crypto.randomUUID`がない場合は`crypto.getRandomValues`でIDを生成する。開始エラーは自動で消さず、閉じるまでエラー文とコードを表示する。実機で報告された一過性の開始エラーについては、元のエラー文が不明のため原因特定には至っていない。

追加の自動テスト：全パズルの解の存在・回転・重なり・盤外、ヒント、リズム判定境界・重複タップ、種類をまたぐ5回上限、Android用ID生成。Firestoreエミュレーターでは卵の状態で承認済みの子供が最初のゲームを開始できることも検証する。
