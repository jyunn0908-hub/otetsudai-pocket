# 育成の実装・検証メモ

仕様元: PR #1 `docs/character-growth-21-day`、08c30cb。
2026-10-04に育成機能とFirestoreルールを既存本番へ公開済み。キャラクターは仮素材で、48×48px・10系統の正式素材は未実装。

## 初版で選んだ未確定事項

- 初回承認時に孵化。その承認日を日本時間のDay 1とする。次のタマゴも、最初の承認まで日数を数えない。
- 遅れて届いた承認は承認時刻に加算。過去の履歴は遡って付与しない。
- 承認済みお手伝いは金額によらず成長10pt。日別上限・ボーナスなし。既存の同日同項目1回制限は維持。
- Day 7/80pt、Day 13/150pt、Day 21/230ptを両方満たすと進化。複数段階が成立した場合は順に抽選・記録し、画面では最新の姿を表示する。
- タマゴ→共通の幼体→2系統→4系統→8最終形態という仮のツリー。名前・絵・候補は確定デザインではない。`growth.mjs`の定義と`growth-view.mjs`の描画を差し替え可能。
- 初版は現在の系統内で等確率。未取得優遇や連続抑制の重みは未設定。抽選関数に重み関数の拡張点がある。取得済みも候補に残す。
- 進化の乱数シードと時刻はトランザクションの外で取得し、再試行中は固定。確定済みの結果は再抽選しない。
- 最終進化したら図鑑に自動記録。次のタマゴは親が確認操作で迎える。最終進化後から次のタマゴまでの承認は交換用ポイントのみ加算。余剰成長ポイントは過去の記録に残し、次へ持ち越さない。
- 課金・追加サーバーなしのため進化の書き込みは親の認証に限定。親の画面で家族データを受信したとき、フォーカス復帰時、表示中の1分ごとに日数条件を再判定する。子供だけが開いている場合、日数だけで成立した進化は親が次に開いたときに確定する。
- 親の端末時計を使用する。親の意図的な時計改変・不正な管理操作への耐性やサーバー時刻だけによる自動進化には、信頼できるバックエンドが必要。

## 保存と権限

`families/{family}.growth` は進行中1サイクルのみ。id、開始日時、段階、キャラクター、累計ポイント、回数、最大4件の確定進化経路、最終進化日時を保持する。既存の家族ドキュメントにフィールドがなければタマゴとして表示。

`families/{family}/growthHistory/{cycleId}` に最終キャラID・名称・開始日・最終進化日・日数・回数・成長pt・経路を1サイクル1文書で保存。図鑑は25件ずつ取得し、追加取得可能。同種でも別サイクルIDで過去を上書きしない。

承認、残高、成長、申請ステータス、必要なら図鑑登録まで同じトランザクション。日数だけの進化も家族データと図鑑登録を同時に更新。図鑑は親のみ作成可能、作成後は書き換え・削除不可。親の複数画面が同時に最終進化を試した場合、一方の書き込みが拒否される場合があるが、成長や図鑑は重複しない。再取得後の状態を使用する。

子供は承認済みメンバーだけ閲覧でき、成長・結果・図鑑を書き換えられない。育成は家族単位のため子供端末交換でも移動やコピー不要。既存1家族1子供仕様を維持。
